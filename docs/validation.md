## 复现方法

保存的 `tests/echo_client.py` 将手动客户端操作整理为五个可选案例。新脚本尚未在当前 Linux 项目上重跑；以上已有结果不等于此脚本已经通过自动化验证。

每次测试都先在终端 A 启动一次服务端：

```bash
./build/tcp_server
```

终端 B 从以下命令选择一条。**完成一个案例后，下一条命令之前先重新启动服务端。**

```bash
python3 tests/echo_client.py normal
python3 tests/echo_client.py fragmented
python3 tests/echo_client.py incomplete
python3 tests/echo_client.py max
python3 tests/echo_client.py oversize
```

客户端逐次读取直到 EOF，再比较完整响应，不能只调用一次 recv 就认定响应完整。客户端设置 3 秒 socket 超时，避免测试无限等待。脚本遇到连接重置或超时会失败，不将任何连接错误直接当作拒绝成功。

服务端退出后，在终端 A 紧接着执行 `echo $?`：正常、分两次发送、最大合法请求预期为 0；不完整和超限请求预期为 1。客户端的成功退出只代表响应符合预期，不验证服务端退出码。

断开后重启重连的补测顺序：先运行 `incomplete`，记录服务端退出码；重启服务端；运行 `normal`，记录返回内容和退出码。如遇地址占用，应如实记录，不能标为通过。

## 尚未验证

- 强制制造 send 部分发送、EINTR、连接重置、端口占用等错误条件。
- 空行、非 ASCII 或包含零字节的请求、一次发送多行。
- 同一个服务进程持续接受新连接（当前未实现）。
- 服务端超时、并发、压力和性能（当前范围不要求）。

长度上限按第一条 LF 结尾的请求计算；客户端不要附带下一条请求。多发数据时关闭连接可能导致客户端收到 RST，而非 EOF，本次已有用例结果不能推广到所有非法输入。
